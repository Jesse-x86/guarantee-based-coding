# GBC 推荐围栏规则集（作者建议）

> 下面只是**作者个人开发哲学下的一种推荐调度方式**，不是 GBC 唯一或必然正确的用法，
> 更不是让 agent 替项目主人作治理决定。Agent 应优先契合主人已有的开发哲学与权限设计；
> 人类也完全可以自行规划、调整或探索其他 agent 分工与调度方式。
>
> GBC 本质上只是把行为依赖变成可重复自动测试的工具，不规定谁必须写代码、维护测试或调用工具。
> 欢迎把它当作基础能力，发展适合自己项目的工作流。以下规则是推荐默认，不是强制沙箱；真正的
> 强制边界仍要靠 agent 框架（例如 Claude Code 的 `pre-tool-use` hook）落地。
> **装了 GBC ≠ 自动安全，也 ≠ 接受了作者的工作方式。**

如果这套哲学适合你的项目，可以把下面的规则纳入 agent 指令（或用框架机制强制）：

1. **任何 agent 都不手编 GBC 管理的图与意图文件。** `gbc.md` 只经 gbc intent（MCP intent 工具 / CLI）修改；
   依赖与保证 JSON 只经 GBC 的 MCP / CLI 工具操作。父子投影、双向边与出生即绿都是
   确定性约束，绕过工具直接改文件会让它们漂移。实现对应的接口产物（若该语言/项目有）
   与保证测试则由实现者随代码一起维护。

2. **实现者对自己引入的局部契约负责。** 它不只写实现：还要查询现有保证、
   登记实际使用的依赖、优先复用已有保证；缺少所需行为保证时，自己写能真正变红的窄测试，
   再创建保证并用 `verify_*` 自证。未登记的行为依赖、未维护的保证测试都算任务未完成。

3. **在授权范围内协调意图与跨范围破坏。** subagent 读取 `gbc.md`，修改需要明确委派权限；
   退休/停用保证、范围外重命名或重构等会影响其他任务的操作，除非 brief 明确
   授权，否则上报顶层 agent 协调。但 gbc.md 只是**现状快照，不是圣旨**：发现它不合理、或它
   需要维护时，起草增量并经 gbc intent 落库。已授权目标与职责内的普通实现、辅助文件拆分和
   文件条目维护无需重复架构审批；改变用途、职责、兼容性、权限或重要约束才需相应授权，
   缺授权时补齐，并遵守项目额外的审批规则。别因「不敢改 gbc.md」就把职责堆进已有文件——
   上帝文件正是防漂移机制的本末倒置。

4. **用框架机制落实“允许局部维护、禁止越界”。** hook 应拦截手编 `gbc.md` / 图元数据、
   未授权的意图修改以及未授权的跨范围破坏操作；不要一刀切屏蔽 subagent 的依赖登记、
   保证创建和验证，否则最了解实现依赖的人无法闭环维护契约。

5. **牢记边界的性质。** GBC 提供的是规则文本与引导，不是安全保证。
   真正阻止越权的是你的框架配置，请据此设置。

6. **只登记你在乎的保证，别把保证当全面测试。** 保证 = 具名行为承诺 + 守护它的窄测试，只为
   「下游真正依赖的行为」登记；能复用已有保证就先复用。没人在乎的保证是负债：破坏要逐个通知
   dependents、verify 变慢、图变臃肿。登记前问：**「如果我在乎的行为现在就坏了，会有测试真的
   变红吗？」** 若否，先写能变红的窄测试，或干脆别登记。

7. **先调查，再沟通实质发现。** 起草变更前先读已有意图、术语、决策及相关代码 / 测试。未决
   选择实质影响行为、范围、兼容性、权限或难以逆转的决定，且证据无法解决时才提问。沿用已有
   授权，按上述授权边界及项目额外的审批规则处理。报告重要进展与实际阻碍，不逐个工具步骤汇报。

8. **按收益派工，不为角色制造交接。** 综合独立性、复杂度判断，以完整可验证的行为切片分工，
   可以跨相关文件；brief 写明全部可写路径，其余只读。派工收益不明显时，一个 agent 可规划
   并实现；负责的 agent 仍须完成最终整体 GBC 验收。

9. **区分开发测试与正式验收。** 允许在正确环境中直接运行未登记测试和定向调试；先红再绿
   可选，不强制回放。出生即绿仍约束正常启用保证的正式创建及测试 / executor 更新，不用停用保证绕行
   TDD。最终验收经 GBC，并审查契约 / 测试变更：GBC 执行用户维护的测试，不能仅靠统一入口
   识别削弱断言。green 只表示无 failed，不等于验收完整；heavy 跳过、停用保证、零执行结果
   都须明确报告为未验证范围。

完整流程见随包的 **gbc-workflow** skill，MCP / CLI 均可使用；**gbc-cli** 是 CLI 命令适配器。
有意义的测试保护消费者实际依赖的承诺：范围聚焦、断言充分、不绑定偶然实现；精确值、顺序、
错误码属于契约时就精确检查。出生即绿本身不证明缺陷
辨识力。复用术语，按已有项目文档约定保存重要决策理由，不要求新建上下文文件或把历史塞进 `gbc.md`。
