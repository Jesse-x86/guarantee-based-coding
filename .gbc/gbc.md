# 意图
让代码在明确契约和验证证据的支持下被安全修改。把模块间的依赖从隐含变成**显式、可执行、可验证的保证**：修改后运行已登记测试，提供消费者所依赖行为的检查结果。GBC 执行项目自管测试，不自动证明断言充分或识别被削弱的契约；测试质量和变更仍需审查。本仓既是这套方法的实现，也是它的第一个使用者（自己管理自己的 `.gbc`）。

**不可破的本体不变量（改任何层都要守）**：保证是一等公民、身份是具名 id（如 config.llm.get_model.returns_loaded，≠测试路径）；多对一——一条保证可被多个消费者共享，dependents 是消费者文件清单，命中已有保证则追加 dependent 复用、不另写测试；双段自包含 meta——每个代码文件一份 .gbc json，provides（作 provider）+ depends_on（作 consumer），symbol 级依赖“免费”（guarantees: []、无测试无反向边），依赖行为而非签名时才升级具名保证；出生即绿——正常启用保证的创建、测试或执行器变更时当场跑、不过则拒绝登记；开发期允许未登记测试先红再实现到绿，最终验收仍经 GBC，停用不作为普通 TDD 绕行手段；退休保护——dependents 非空的保证拒绝删除；门禁二元——跑了的保证只有过/挂，没跑的（heavy/disabled 跳过）响亮报告但不染红，green = 无 failed；GREEN 不表示任务验收完整，零执行没有行为证据；heavy 是成本秩 int + 自动运行授权（批量只跑 heavy ≤ 阈值，register/点名 verify 无视该阈值）；零侵入 + 语言无关——元数据全在 .gbc，怎么跑测试抽象成 executor 配置。

**分层（自外向内，依赖只能向内）**：interface（cli/mcp 表面、base 编排/IO）→ core（纯逻辑 + 跑测试）→ models（数据契约）；config/utils 为横切支撑。外层可换形态（cli/mcp/未来 GUI），引擎不动。

# 文件

## demo/
⚠️ OBSOLETE — 本目录已废弃，不再维护。

原用途：GBC 的交互式演示套件（Runner + 剧本 + 演示项目源码），用于展示 GBC 三条核心机制（强测试门禁拦截 / 弱测试门禁失效 / 出生即绿）及集成前后工作方式对比。

废弃原因：表现形式不佳，且当前无维护计划。文件保留供参考，但不应作为使用入口；新用户请直接读 docs/ 下的文档。

下属子目录（runner / scenarios / projects）随本目录一并废弃。

## gbc/
GBC 可分发 Python 包，pip 安装后提供 gbc。entry.py 是纯分发器，组合保证引擎、架构意图 intent、离线手册 doc 和服务入口。随包手册来自 docs/ 单一内容源，安装后独立于源码仓库；项目状态仍由目标项目 .gbc/ 持有。

## build_support.py
setuptools 构建扩展：将 docs/en 与 docs/zh 五个手册主题复制到 wheel 的 gbc/assets/docs；源分发保留手册及构建支持，可独立重建 wheel。

## docs/
面向使用者的产品说明、案例、双语手册与开发记录。用可核对的示例解释 GBC 的意图和行为契约，区分工具能力、工作流约定与验证证据；固定离线手册主题由构建配置选取。
