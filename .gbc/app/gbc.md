# 意图
实现本体的全部代码。分层自外向内、**依赖只能向内**:`interface`(表面 + 编排/IO)→ `core`
(纯逻辑 + 跑测试)→ `models`(数据契约);`config` 与 `utils` 为横切支撑,被各层使用但不反向依赖业务层。
每个子文件夹有自己的 `gbc.md` 说明意图与内部约束。

# 文件

## config/
回答三个问题:在哪个项目上工作、meta 写入保留几份备份、怎么跑测试。多为进程内单例 + 环境变量驱动。

## core/
保证系统的核心逻辑与"怎么真的把测试跑起来"。**纯模型操作**:不解析路径、不读写 `.gbc` 文件
(那是 base 的活)。进出本层的文件路径一律是**项目相对字符串**。

## interface/
把引擎能力暴露成"人/agent 能用的形态",并把"外部形态"与"内部实现"彻底解耦:cli、mcp(未来可
能还有 GUI)都只是薄表面,真正的编排、路径解析、文件读写收在 `base` 一处。换表面不动引擎。

## models/
所有层共享的 pydantic 模型。**模型即契约**:无业务逻辑、无 IO。改一个字段就是改契约,下游(core /
interface / 落盘的 `.gbc` json)全靠它,要慎重。

## utils/
无业务语义的通用工具:`.gbc` 路径映射、json↔模型、原子写文件。被各层使用,不依赖业务层。
