# 把 GBC 接入你的 agent

这份指南面向 AI：用户说“给当前项目装 GBC”时，按下面步骤完成接入并验证。
`gbc setup` 只输出指南，不执行安装或配置；它已经能运行，通常说明 GBC 程序已安装，
剩下的是让当前 agent 在这个项目中使用它。AI 初次发现 GBC 仍需已有命令、文档或
skill 等可用入口；这份输出不会让客户端自动发现 GBC。

## 1. 确认项目与运行环境

确认用户当前目标项目的绝对路径、agent 客户端及其 MCP 配置方式，以及客户端实际
启动进程的系统、解释器和 PATH。核对现有 GBC 命令能否在该环境运行；不要混用 Windows
与 WSL 路径。确实未安装时，按项目文档或用户提供的可信来源安装，不猜测 pip 包名。
一份 GBC 程序可以供多个项目共用；每个项目的 MCP 配置必须显式绑定自己的绝对路径。

## 2. 持久接入当前项目的 MCP

先查当前客户端支持的项目级 MCP 配置位置与格式，再检查已有配置。在当前项目中
增加或核对 GBC stdio 条目，保留其他 server 和用户设置；已有正确条目就复用。
这是持久的项目级绑定，不是会话内切换；不要把当前项目写死到全局 MCP 配置。

启动入口：`gbc mcp up <项目根的绝对路径>`。通用配置模板如下，替换示例路径，
并按客户端 schema 放入正确位置；这不是所有客户端通用的完整配置文件：

```json
{{
  "command": "gbc",
  "args": ["mcp", "up", "/abs/path/to/your/project"]
}}
```

客户端 PATH 找不到 `gbc` 时，用已核对的解释器绝对路径：

```json
{{
  "command": "/abs/path/to/python",
  "args": ["-m", "gbc.entry", "mcp", "up", "/abs/path/to/your/project"]
}}
```

JSON 中 Windows 路径可用正斜杠；路径有空格也保持为一个参数。项目状态保存在该项目
的 `.gbc/` 下，首次写入时创建，不必为了接入而预先生成架构内容。
若客户端不支持项目级 MCP，说明限制并使用下面的 CLI 方式，不改成全局固定项目。

## 3. 重连并核对实际目标

按客户端方式重新加载 / 重连 MCP。通过客户端显示的实际启动命令、参数或启动日志，
核对加载的是目标项目的绝对路径，然后做只读调用，例如 MCP 的 `tree`。
已有项目应将返回内容与目标项目的已知内容核对；空树只能说明调用成功，不能单独
证明绑定正确。客户端若不显示生效参数且项目没有可辨识内容，明确报告目标绑定
尚未验证，不通过写入测试数据来冒充只读验证。

## 4. 选择工作流指导与调用入口

**gbc-workflow** skill 指导意图起草、行为测试及术语 / 决策复用，**MCP 与 CLI 均可使用**。
无 MCP 时，**gbc-cli** 提供对应的 shell 命令。随包 skill 目录为：

```
{skills_dir}
```

先阅读相关 `SKILL.md`；仅在客户端需要时按其项目级方式接入，不自动创建全局
skill 或 memory。CLI 可在项目目录运行，也可在叶子命令后放 `--project` / `-C`
显式指定目标，例如只读查看：

```
gbc tree show --project "/abs/path/to/your/project"
```

## 阅读离线手册

`gbc doc list --lang zh` 列出随包附带的五个主题；用
`gbc doc read onboarding-agent --lang zh` 阅读接入指南，或用
`gbc doc search "保证" --lang zh` 搜索。无需项目或网络；`--help` 仍是简短语法参考。
对应 MCP 工具为 `doc_list`、`doc_read`、`doc_search`。项目架构使用 `gbc intent` / `intent_*`；
0.3.0 已移除原先用于意图的 `doc` 名称。

## 用之前，先记住三件事

- **gbc.md 是现状快照，不是圣旨。** 它防的是架构漂移，不是架构演进——想改就走「起草 →
  送人类审批 → 经 gbc intent 落库」，正当演进不是违规。别因为「不能手编」就把职责全塞进已有
  文件——上帝文件正是防漂移机制的本末倒置。
- **保证 ≠ 全面测试。** 每条保证是窄测试守护的具名行为承诺，只登记你在乎且被依赖的行为，能复用
  先复用；没人在乎的保证是负债。
- **多与人类沟通。** 报告完成的接入、验证证据和实际阻碍，不把未验证的目标绑定报成成功。

## 接入的边界

GBC 给的是能力，不是强制沙箱。`gbc rules` 说明规则，强制执行需要 agent 框架的
hook 等机制另行接入。“装 GBC”不授权自动部署强制 hooks、生成项目架构内容或全局
skill / memory。按已授权范围完成接入；额外行为另行对齐。
