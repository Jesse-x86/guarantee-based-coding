# guarantee-based-coding —— 工具本体

让代码即使在不被完全理解的情况下也能被安全修改。把模块间的依赖从隐含变成**显式、可执行、
可验证的保证**:修改后机械跑测试,正确性从"AI 觉得改对了"变成"所有被依赖的保证仍通过"的布尔判定。
本仓既是这套方法的实现,也是它的第一个使用者(自己管理自己的 `.gbc`)。

## 不可破的本体不变量(改任何层都要守)

- **保证是一等公民,身份是具名 id**(如 `config.llm.get_model.returns_loaded`),**不是测试路径**——
  改测试文件名不改变保证身份。
- **多对一**:一条保证可被多个消费者共享;`dependents` 是消费者文件清单。命中已有保证 → 追加
  dependent 复用,**不另写测试**(去重)。
- **双段自包含 meta**:每个代码文件一份 `.gbc` json,`provides`(作 provider)+ `depends_on`
  (作 consumer)。symbol 级依赖是"免费"的(`guarantees: []`,无测试、无反向边);依赖的是
  **行为**而非签名时才升级成具名保证。
- **出生即绿**:create / 改动测试时当场跑,不过则拒绝登记——绝不留下没验证过的保证。这是系统
  唯一的完整性不变量,**没有跳过它的后门**。
- **退休保护**:`dependents` 非空的保证**拒绝删除**;必须先沿依赖线修复/迁移。删 active 保证 =
  悄悄弄坏下游。
- **门禁二元**:跑了的测试只有 过/挂;没跑的是"缺席"(heavy 跳过),响亮报告但不染红。
  `green = 无 failed`。
- **heavy 是成本秩(int)+ 自动运行授权等级**:批量只跑 `heavy <= 阈值`(默认 0),其余跳过并报告;
  register / 点名 `verify_guarantee` 无视它、永远跑。
- **零侵入 + 语言无关**:元数据全在 `.gbc/`,目标代码保持干净;"怎么跑测试"抽象成 executor 配置。

## 分层(自外向内,依赖只能向内)

`interface`(cli / mcp 表面、base 编排/IO)→ `core`(纯逻辑 + 跑测试)→ `models`(数据契约)。
`config` / `utils` 为横切支撑。外层可换形态(cli/mcp/未来 GUI),引擎不动。

## app

工具的 Python 包根。每个子层有自己的 `gbc.md` 说明意图与内部约束;依赖图与具名保证见各文件的
`.gbc` json。
